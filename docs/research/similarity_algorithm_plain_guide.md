# A股相似阶段搜索算法说明（通俗版）

## 一句话结论

当前工具先不急着押注某一个“最强算法”。更稳妥的做法是：保留原来的默认算法，再新增几种候选算法，用固定样本生成核验图集，最后用肉眼判断哪种算法更像真正的走势相似。

## 这次优化解决什么问题

以前系统主要比较两件事：

1. 股价走势路径像不像。
2. 区间收益、波动率、回撤、量价关系这些特征像不像。

这个方法简单、可解释，但有一个缺点：它更偏“价格曲线长得像”，有时会忽略“涨跌节奏像不像”。

这次新增的研究框架，就是为了把问题拆开看：

- 价格曲线像不像。
- 每天涨跌节奏像不像。
- 加上波动、回撤、量价特征后还像不像。
- 如果日期稍微错位，走势是否仍然相似。

## 两类搜索分别在做什么

### 1. 同一标的历史时序相似

问题是：

> 这只股票或指数，过去有没有出现过和当前这段走势相似的阶段？

例子：

- 目标：创业板指 `399006.SZ`
- 当前区间：2024-03-04 至 2024-03-31
- 系统在它自己的历史 K 线里找相似阶段。

这个模式主要用来回答：

- 当前走势在历史上像哪一次？
- 那一次之后 5/20/60 根 K 线怎么走？
- 历史相似阶段是否有统计参考意义？

### 2. 同一时间横截面相似

问题是：

> 在同一段时间里，哪些股票走势和目标股票相似？

例子：

- 目标：`688603.SH`
- 目标区间：2026-03-25 至 2026-05-15
- 搜索范围：全 A 或某个指数成分。

这个模式主要用来回答：

- 同一市场环境下，哪些股票走出了类似形态？
- 相似股票后 3/5/10 根 K 线表现如何？
- 目标走势是不是某个板块或风格里的共振形态？

## 为什么不直接换成复杂算法

相似搜索很容易出现“看起来科学，实际不好用”的问题。

例如 DTW、Matrix Profile、Foundation Model 都很有名，但直接替换当前算法会有几个风险：

- 结果不一定更符合肉眼直觉。
- 解释难度更高。
- 依赖更重，部署和页面启动容易变慢。
- 一旦算法默认切换，旧结果口径会断掉，无法回退。

所以这次采用更保守的路径：

1. 默认算法不变。
2. 新算法以可选项进入。
3. 所有算法都能生成同一套核验图集。
4. 先看图，再决定哪个算法进入主流程。

## 当前保留和新增的算法

| 算法 | 通俗理解 | 适合看什么 | 当前定位 |
| --- | --- | --- | --- |
| `baseline_price_feature` | 原来的算法，看价格路径和手工特征 | 稳定、可解释、可回退 | 默认算法 |
| `return_shape` | 看每天涨跌节奏是否相似 | 涨跌节奏、形态变化 | 候选算法 |
| `hybrid_shape_v2` | 同时看价格路径、收益节奏和特征 | 综合肉眼相似度 | 主推候选 |
| `dtw_optional` | 允许走势局部快慢错位 | 走势相似但日期不完全对齐 | 可选依赖 |
| `mass_optional_history` | 用 Matrix Profile 思路做历史预筛 | 大规模历史片段检索 | 先放 benchmark |

## 怎么理解新增的距离分项

结果表里会多出几个字段：

- `路径距离`：最终参与排序的形态距离，越小越像。
- `价格路径距离`：价格归一化后的曲线距离，越小越像。
- `收益路径距离`：日收益节奏距离，越小越像。
- `综合相似度`：把路径相似度和特征相似度加权后的总分，越高越像。

简单理解：

- 如果价格路径距离小，说明曲线形状像。
- 如果收益路径距离小，说明涨跌节奏像。
- 如果两者都小，通常肉眼更容易觉得像。

## 日期容错为什么仍然保留

横截面搜索里，目标区间不应该被扩大。

原因是：

- 扩大目标区间会把后验观察收益混进相似度计算。
- 用户选的是一段关键走势，前后额外 K 线可能稀释目标形态。
- 停牌、缺数据、自然日和交易日不一致，会让精确日期产生误判。

更好的做法是：

> 目标窗口不变，只允许候选股票的窗口整体前后平移 N 根交易日。

这样既避免精确日期误差，也不污染后验收益统计。

## 核验图集怎么看

新增 benchmark 命令会输出三类文件：

- `benchmark_summary.csv`：每个样本、每个算法的运行时间、结果数量、跳过数量。
- `benchmark_results.csv`：每个算法的 Top 结果和距离分项。
- `benchmark_gallery.html`：目标窗口和 Top 样本的走势图，方便肉眼复核。

建议先看 HTML 图集：

1. 先看目标窗口。
2. 再看每个算法给出的 Top 样本。
3. 判断哪种算法最符合“肉眼走势相似”。
4. 再回头看收益统计，不要先被后验收益影响判断。

## 页面上怎么使用

Streamlit 页面里，历史时序相似和横截面相似都新增了“相似算法”选择器。

建议使用顺序：

1. 先用默认 `baseline_price_feature` 跑一遍。
2. 再切到 `return_shape`，看涨跌节奏相似结果是否更自然。
3. 再切到 `hybrid_shape_v2`，看综合结果是否更符合肉眼。
4. 如果安装了 `aeon` 或 `tslearn`，再试 `dtw_optional`。

默认不要直接依赖 `dtw_optional`，因为它更慢、依赖更重，也更难解释。

## 当前建议

短期建议：

- 默认继续用 `baseline_price_feature`。
- 研究核验重点看 `hybrid_shape_v2`。
- `return_shape` 用来判断涨跌节奏是否更贴近肉眼。
- `dtw_optional` 只作为对照，不作为默认。

中期建议：

- 固定一批典型样本。
- 每次算法调整都生成同一套核验图集。
- 只在图集明显改善后，才考虑提高新算法权重。

长期建议：

- 如果后续积累人工标注，再考虑 shapelet 或 embedding 模型。
- Foundation Model 先作为研究观察，不进入当前主链路。

## 可执行命令

```bash
python -m ashare_cross_section_similarity benchmark \
  --cases docs/research/similarity_benchmark_cases.yaml \
  --algorithms baseline_price_feature,return_shape,hybrid_shape_v2,dtw_optional \
  --output outputs/research
```

生成后先打开：

```text
outputs/research/benchmark_gallery.html
```

## 当前判断

这次改动的核心不是“算法更复杂”，而是建立了一个可复验的研究流程：

- 旧算法不丢。
- 新算法可切换。
- 结果可对比。
- 图集可肉眼核验。
- 后验收益只作为辅助统计，不参与形态相似度判断。
